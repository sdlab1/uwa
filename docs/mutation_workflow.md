# Канонический workflow харнесса (`devh`)

> Этот файл СГЕНЕРИРОВАН из кода (`devh workflow`). Не править руками:
> канон живёт в `devharness/src/commands/workflow.rs` и
> `devharness/src/commands/mutate.rs`.

## Что изменилось (2026-10-22)

Раньше мутационный аудит вёлся внешним скриптом
(`devharness/tools/mutants-watch.sh`), а полный сьют запускался через
`bash devharness/test.sh`. Оба входа требовали «руками», а логи разбирались
ad-hoc. Теперь у харнесса ровно четыре входа:

| вход | что это | код возврата |
| --- | --- | --- |
| `devh mutate ...` | единственный вход в мутационный аудит (cargo-mutants внутри) | 0 / 1 / 2 |
| `devh test` | единственный вход в полный сьют (`devharness/test.sh` внутри) | 0 / 1 / 2 |
| `devh next` | оракул следующего шага (ровно одна команда) | всегда 0 |
| `devh workflow` | печать этого канона из кода | 0 |

Внешний watcher и корневой `MUTATION_WORKFLOW.md` удалены (без обёрток и
fallback): наблюдение живёт в харнессе (`core/watch.rs`: inotify + poll +
труба завершения процесса), без sleep-циклов.

## Канон (из кода)

```
=== ИСТОЧНИКИ ИСТИНЫ (по убыванию авторитета) ===
  1. код харнесса (commands/workflow.rs, commands/mutate.rs)
  2. devh workflow   — печать канона из кода
  3. справка команды (devh mutate help)
  4. docs/mutation_workflow.md, AGENTS.md
  5. память агента
  Если память агента противоречит devh workflow — правда devh workflow.

=== КОДЫ ВОЗВРАТА (все команды) ===
  0 — успех (чисто / шаг выполнен)
  1 — actionable проблема проекта (дыра в тестах, красный гейт, FAIL в сьюте)
  2 — среда не готова / нечего проверять (нет аудита, аудит идёт, нет инструмента)
  3 — внутренняя ошибка харнесса (наблюдатель отвалился) — НЕ чинить код проекта

=== ПРАВИЛА ===
  R1  мутационный аудит запускается ТОЛЬКО через `devh mutate`; руками cargo-mutants — НЕЛЬЗЯ
  R2  внешнего watcher'а нет; наблюдение — родное (inotify), без sleep-циклов
  R3  дублирующих документов-«вторых источников истины» нет (MUTATION_WORKFLOW.md удалён)
  R4  пойман = ТОЛЬКО CaughtMutant; kill-rate = 100 * caught / (done - unviable)
  R5  выживший/таймаут/unviable/неопознанный исход/битые детали → финальный вердикт НЕ может быть «чисто»
  R6  Unviable — дыра с нулевой терпимостью (чинить код, пока мутант не собирается)
  R7  живой вывод — событийный (inotify), без внешнего скрипта и без sleep-цикла агента
  R8  сьюты запускаются ТОЛЬКО через `devh test` (полный лог + итог PASS/FAIL в stdout и в коде возврата)
  R9  git принадлежит харнессу: агент НЕ делает git add/commit/push/rebase/reset/checkout/stash
  R10 одна зона аудита за раз: mutants.out — один на прогон
  R11 фоновый аудит не трогает дерево агента (--in-place запрещён для `devh mutate start`)
  R12 артефакты аудита — read-only для агента (правка руками = читерство, результат обнуляется)
  R13 никаких «ручных» команд в bash: всё, что нужно от харнесса, делается его подкомандами
  R14 не гадать: непонятно, что делать дальше → `devh next` печатает ровно одну следующую команду

=== СОСТОЯНИЯ (маршрут) ===
  S0  нет .harness/config                     → devh init
  S1  item создан, агент не запускался         → devh run <ID>
  S2  идёт агент/прогон                       → devh logs <ID>
  S3  гейт упал, fix-раунд                     → внутри devh run (промпт несёт список проблем)
  S4  гейты зелёные, нужен коммит              → devh commit <ID>
  S5  коммит есть, не смержено                 → devh merge <ID>
  S6  мутационный аудит идёт                   → devh mutate problems (или watch, если проблем нет)
  S7  аудит завершён, есть дыра                → devh mutate problems
  S8  аудит завершён, чисто                    → devh commit <ID> / devh merge <ID>
  S9  ничего не начато, но есть спеки          → devh auto --from specs/ --max 5
  S10 лимит фиксов исчерпан                    → devh abort <ID>
  S11 мусор: старые worktree/логи              → devh clean / devh sweep --maxsize 20G

=== КОМАНДЫ ===
  devh init                    инициализация репозитория
  devh new <спека>             создать item
  devh run <ID>                прогон агента + гейты + фиксы
  devh bg <ID>                 фоновый прогон (наблюдение — devh ps)
  devh logs <ID>               хвост лога item'а
  devh commit <ID>             коммит (делает харнесс)
  devh merge <ID>              rebase → ff-push → лог
  devh abort <ID>              списать item
  devh list                    список item'ов
  devh ps                      живые прогоны
  devh doctor                  диагностика окружения
  devh clean / devh sweep      уборка мусора
  devh test                    полный сьют (test.sh): полный лог + PASS/FAIL + код возврата
  devh test --list             список проверок сьюта
  devh test --case <N|имя>     точечная проверка (фильтр отчёта)
  devh mutate start|status|watch|problems|verdict|stop   мутационный аудит
  devh next                    оракул: ровно одна следующая команда (всегда rc=0)
  devh workflow                печать этого канона из кода

=== ЗАПРЕЩЕНО (R1/R2/R9/R13) ===
  ✗ cargo mutants / cargo-mutants руками        → только devh mutate
  ✗ bash devharness/test.sh руками              → только devh test
  ✗ внешний watcher/sleep-цикл/фоновый скрипт   → только devh mutate watch
  ✗ ad-hoc разбор логов (grep/awk по outcomes)  → devh mutate problems / status --json
  ✗ git add/commit/push/rebase/reset/checkout   → devh commit / devh merge
  ✗ правка артефактов аудита руками             → результат обнуляется
  ✗ тяжёлые прогоны параллельно и при перегруженном CPU → сначала свежая проверка нагрузки
  ✗ убивать процессы соседнего агента            → ждать или останавливать ТОЛЬКО свой прогон

=== БЕЗОПАСНОСТЬ (соседние агенты) ===
  Тяжёлые проверки (мутации, полный сьют) — последовательно, не параллельно.
  Перед тяжёлым прогоном — свежая проверка нагрузки (не устаревший снимок).
  Процессы соседнего агента НЕ убивать: ждать или останавливать только свой прогон.
  Порог нагрузки: HARNESS_MUTATE_MAX_LOAD (по умолчанию max(4, 2*CPU)), off — отключить.

devh mutate — единственный вход в мутационный аудит

  devh mutate start <args>   запустить аудит (args = флаги cargo-mutants).
                              Процесс ОТДЕЛЬНЫЙ (setsid): тул/терминал могут
                              умереть — аудит продолжится. Печатает, что
                              запускать дальше. Фоновый аудит идёт в copy-режиме
                              (без --in-place): дерево агента не мутируется.
  devh mutate status          мгновенный снимок: легенда + процент-пилюля +
                              счётчики (✓/✗/⏱/⊘) + ETA + текущий мутант.
                              rc=1, если уже есть проблемы. Ничего не ждёт.
  devh mutate watch           живой CLI: строка обновляется на месте по
                              событиям ФС (inotify), пока идёт прогон
                              (--timeout N — ограничить секунды).
  devh mutate problems        руководство к действию: что чинить (файл:строка,
                              замена, жанр, исход). rc=1, если есть проблемы.
  devh mutate verdict         финальный вердикт: 0 = чисто, 1 = дыра
                              (выжил/таймаут/не компилится/неопознанный исход/
                              повреждённые детали/упавший инструмент),
                              2 = прогон ещё идёт / аудита нет.
  devh mutate stop            остановить идущий аудит (группа cargo-mutants).
  devh mutate help            эта справка.

Когда что:
  • закрыл зону кода      → start (ядро: --config devharness/cargo-mutants.toml)
  • перед мержем           → verdict (код возврата — гейт)
  • «что сейчас?»         → status
  • «что чинить?»         → problems
  • смотришь в терминал    → watch

Семантика исходов (cargo-mutants 27.1.0):
  ✓ CaughtMutant  — пойман: единственный результат, закрывает вопрос.
  ✗ MissedMutant  — выжил: дыра в тестах, чинить.
  ⏱ Timeout       — тест-фаза не уложилась: пойман не был, чинить.
  ⊘ Unviable      — мутант не компилируется: провал (ноль терпимости), чинить код.

Пока есть ✗/⏱/⊘/неопознанный исход/битые детали — вердикт НЕ может быть
«чисто». Руками cargo-mutants НЕ запускать — только через devh mutate.
```

## Семантика мутационного исхода (cargo-mutants 27.1.0)

| исход | что значит | попадает в killed? |
| --- | --- | --- |
| `Success` (baseline) | базовая сборка прошла — это НЕ мутант | нет |
| `CaughtMutant` | тест поймал мутанта | **да** (единственный успех) |
| `MissedMutant` | выжил — дыра в тестах | нет, чинить |
| `Timeout` | тест-фаза не уложилась — поимки не было | нет, чинить |
| `Unviable` | мутант не компилируется | нет, чинить код (нулевая терпимость) |
| `Failure` / неизвестный исход | неопознанный исход мутанта | нет, чинить |

Формулы: `killed = caught`, `testable = done - unviable`,
`kill_rate = 100 * caught / testable`, `unresolved = missed + timeout`.

Пока есть missed / timeout / unviable / неизвестный исход / отсутствуют или
повреждены детали аудита — финальный вердикт НЕ может быть «чисто».

## Problem-first

Проблема (выживший/таймаут/unviable) попадает в отчёт и в `problems.json`
сразу, с `file:line`, заменой и жанром — это то, что уходит в следующий
fix-промпт. Агент начинает чинить, не дожидаясь конца аудита. Синхронный
in-place гейт может остановить группу процессов; фоновый аудит идёт до конца
и не мутирует дерево агента (только copy-режим или отдельная worktree).

## Файлы артефактов аудита

```
.harness/mutate/state.json      состояние прогона (running/done/failed/stopped)
.harness/mutate/problems.json   живой список проблем (file:line, замена, жанр)
.harness/mutate/verdict.json    финальный вердикт (счётчики, kill-rate)
.harness/mutate/live.log        живые кадры + журнал доложившихся проблем
.harness/mutate/cargo.log       полный stdout/stderr cargo-mutants
.harness/mutate/supervisor.log  лог супервизора
```

Артефакты аудита — read-only для агента: правка руками = читерство.
