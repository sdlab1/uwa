## E2 — строгий `is_debt` (реально 30–45 мин)

**Решение — инверсия дефолта через грамматику префиксов:**

```rust
/// Конвертация — только явная грамматика; всё остальное — долг.
const CONVERTS: [&str; 3] = ["гейт:", "стаб:", "принял риск:"];

impl Escape {
    pub fn is_debt(&self) -> bool {
        let r = self.reaction.trim().to_lowercase();
        !CONVERTS.iter().any(|p| r.starts_with(p))
    }
}
```

**RED-спека (первый тест падает на текущем коде):**

```rust
#[test]
fn debt_is_default_free_text_is_debt() {
    for r in ["ok", "later", "wontfix", "починил руками", "стаб-кандидат №14"] {
        assert!(parse_escape_line(&line(r)).unwrap().is_debt(), "«{r}» = долг");
    }
    for r in ["гейт: NO-IGNORED", "стаб: №14", "принял риск: env", "ГЕЙТ: x"] {
        assert!(!parse_escape_line(&line(r)).unwrap().is_debt(), "«{r}» = конвертация");
    }
}
```

**Грабли, которые съедят сэкономленные 15 минут:**
1. **Фикстуры стали контрактом.** Тест B1 `"стаб-кандидат №14"` (assert is_debt == false) ломается — это не «правка теста», это смена контракта: переписать в `"стаб: кандидат №14"`. Тот самый прецедент, который ты зафиксировал для корпуса A5 — здесь он же, в миниатюре.
2. **Миграция живого ledger.** Старые строки с вольными реакциями молча станут долгом → уровень уйдёт в L0. Это фича (строгий дефолт), но перед слиянием пройди свой `.harness/escapes.md` руками и перепиши реакции в грамматику. Зафиксировать в `rust_build.md`.
3. **Подсказка пустого ledger** в `report()` обязана раскрыть грамматику — иначе человек записывает «ok» и не понимает, почему L0.

**Приёмка:** тесты выше зелёные; `report()` печатает грамматику; секция 47 обновлена; мутанты на `CONVERTS`-итерацию ловятся (мутант `is_debt → true`/`false` убивается обеими ветками теста).

## E4 — здоровье лога (30–45 мин)

**Решение — не просто WARN, а типизированная статистика:**

```rust
pub struct LogHealth { pub headers: u32, pub dated: u32 }

pub fn log_health(log_md: &str) -> LogHealth {
    // headers: все "## W-…" заголовки; dated: те, где date_in_parens удался
}

pub fn streak_of(log_md: &str, escapes: &[Escape]) -> (u32, bool /*distrust*/) {
    let h = log_health(log_md);
    let undated = h.headers.saturating_sub(h.dated);
    let distrust = h.headers > 0 && undated * 2 > h.headers;  // >50%
    // streak как сейчас; distrust тянется наружу
}
```

**Опция B (дёшево, убирает same-day двусмысленность):** у побега есть `session: "W-095"` — искать его заголовок в log.md и считать заголовки **после него в файле** (log.md append-only = файловый порядок есть монотонные часы). Дата-режим — фолбэк, если сессии нет в логе. Это точнее сравнения дат «того же дня = до». +30 мин, можно вторым коммитом.

**Где светить:** строка в `report()` (`⚠ лог: 4/10 сессий без даты — streak недоверенный`) + soft-warn в doctor (те же чистые функции). `level_line` не менять — уровень уже консервативен, WARN для человека.

**RED:** сидированный лог, 6 заголовков / 4 без даты → `distrust == true` (функции нет — тест не компилируется/падает; дальше граница 50%: 5/10 → false, 6/10 → true).

**Грабля:** пустой лог → distrust = false («нет данных» ≠ «ложь»); дрейф заголовка без « — » всё ещё парсится текущим `split(" — ").next()` — не «починить» случайно это поведение, оно в `sessions_in` уже так живёт.

## E3 — свежесть корпуса (реально 45–60 мин, не 30)

**Ключевое проектное решение, которого нет в плане: относительно чего мерить возраст?** Wall clock (`SystemTime::now`) — нетестируемо и вносит недетерминизм в тесты. **Референс = дата последней сессии в log.md** — «корпус не старше последних улик», и лог уже есть единые часы системы. Без chrono, дни по civilian-алгоритму (Hinnant, ~10 строк, чистая функция):

```rust
pub const CORPUS_FRESH_DAYS: i64 = 14;   // config CORPUS_MAX_AGE_DAYS

pub enum Staleness { Fresh, Stale { age: i64 }, Unknown }

pub fn days_from_civil(y: i64, m: u32, d: u32) -> i64 { /* Hinnant */ }
pub fn days_between(a: &str, b: &str) -> Option<i64>  // None = не ISO
pub fn staleness(corpus_date: &str, ref_date: &str, max: i64) -> Staleness
```

**Проводка:** `aggregate()` тянет ref_date из log.md; `Stale | Unknown` → уровень не повышается, но **отчёт показывает реальные цифры с пометкой**, а не нули: `корпус: 13/13 (2026-10-01, устарел 21д > 14)`. Человек видит, что прокрутить test.sh достаточно — это важно, «0/0» бы звало чинить несуществующее.

**Граница:** age == max → Fresh (stale строго больше; тест на границу — иначе мутант `>` ↔ `>=` живёт). Doctor: WARN при Stale. CONFIG_KEYS 36→37, init-шаблон комментирован.

**Грабля:** corpus.json свежее последней сессии (прогнали test.sh между сессиями) — это нормальный случай, age ≤ 0 → Fresh, не клампить в Unknown.

### E3.1 Реализация (escapes.rs)

**Корпус — снимок, а не live-данные.** `corpus.json` пишет `test.sh` по окончании полного прогона (корпус A5). Формат три поля:

```json
{"caught": 13, "total": 13, "date": "2026-10-19"}
```

- `caught`/`total` — kill-rate; `total == 0` → `kill_rate = 0.0`.
- `date` — строго `YYYY-MM-DD`, до дня.

**Путь:** `corpus_path(store) = store.dir.join("corpus.json")`. `std::fs::read_to_string`; ошибка → `None` в `aggregate` → corpus `None` → `Freshness::Unknown`.

**Референс — дата последней сессии из `log.md`, НЕ wall-clock:**

```rust
pub fn sessions_in(log_md: &str) -> Vec<String> { /* ## W-NNN — title (YYYY-MM-DD) */ }
pub fn latest_session_date(log_md: &str) -> Option<String> {
    sessions_in(log_md).into_iter().max()
}
```

`sessions_in`: `strip_prefix("## ")`, `id = rest.split(" — ").next()`, `id.starts_with('W')`; `date_in_parens` ищет последние `(...)`, проверяет `looks_like_date` (10 байт, `b'-'` на позициях 4/7); `parse_date_days` проверяет `m ∈ [1,12]`, `d ∈ [1,31]`.

**Дни — Hinnant `days_from_civil`, без chrono:** ~20 строк, `saturating_*` везде (мутант `replace → Default::default()` компилируется, а вычитание без saturating даёт underflow).

**Трёхсостоянийный вердикт (`corpus_freshness`):**

| Состояние | Условие | `allows_level` | `note()` |
|---|---|---|---|
| `Fresh` | `0 ≤ age ≤ max_days` | `true` | `None` |
| `Stale` | `age > max_days` | `false` | `«устарел {age}д > {max}»` |
| `Unknown` | `parse_date_days → None` | `false` | `«дата не читается»` |

**Граница:** `age == max` → Fresh (stale строго `>`). Мутант `>`↔`>=` убивается обеими ветвями тестами.

**Встраивание:** `aggregate(store, max_days)` читает `escapes.md` + `log.md` + `corpus.json`; `fresh` → `level_line` печатает всегда:
- `Fresh` → `«корпус 13/13»`
- `Stale` → `«корпус 13/13 (2026-10-01, устарел 21д > 14)»`
- `Unknown` → `«корпус 13/13 (дата не читается)»`
- `corpus == None` → `«корпус: нет данных»`

`autonomy_level` получает `fresh.allows_level()`: `Stale`/`Unknown` → `false` → L0. **Конфиг:** `RunConfig.corpus_fresh_days: u32` default = `CORPUS_FRESH_DAYS = 14`.

**Что ломает свежесть:** (1) атаки не покрыты новыми тестами → `Stale` режет уровень при 100% kill; (2) `test.sh` не перегнан → `Stale` пока не пересчитан; (3) дата в `log.md` не читается → `Unknown` → L0.

**Откат:** `CORPUS_FRESH_DAYS=0` → всегда Fresh. `-1`/пусто/мусор → 14.

**Тесты в `escapes.rs`:** 7 кейсов `corpus_freshness`; `level_line` для всех состояний. Интеграция: `report_stale_corpus_blocks_level`, `report_no_corpus_is_no_data_not_hundred`.

## E1 — петля фальсификации (1 ч, но с двумя решениями внутри)

**Решение 1 — детерминизм выбора.** Сэмпл не «каждая N-я по времени», а **W-id % AUTONOMY_SAMPLE == 0**. Номера выдаёт харнесс → агент не может влиять на попадание в выборку, человек не выбирает удобные сессии:

```rust
pub const AUTONOMY_SAMPLE: u32 = 3;

pub fn sampled_ids(log_md: &str, every: u32) -> Vec<String> // W-003, W-006, …
```

`devh escapes --sample`: печатает выбранные W-id **+ готовую команду** (`git show <sha>` из записи сессии в log.md; если sha не хранится — `devh logs W-NNN` подсказкой). Friction — главный убийца этой петли: команда должна быть copy-paste.

**Решение 2 — чистая выборка тоже записывается, иначе она невидима.** `.harness/samples.md`: `дата | W-NNN | чисто` (или `| escape: blind:level | …` — и тогда второй строкой руками в escapes.md). Report: `выборка: 2/2 чисто; blind:level ×1`.

**Чего НЕ делать в v1:** не заводить выборку в `autonomy_level`. Сначала копим калибровочные данные — тот же паттерн, что B1 (инструмент измеряет, решение за человеком). Заводить в уровень — после первых расхождений, когда известно их base rate.

**RED:** integration — сид 9 сессий, `--sample` печатает ровно W-003/006/009 + команду; samples.md с двумя «чисто» появляется в report.

**Doctor-напоминание:** «выборка отстаёт: последний sample старше N сессий» — единственная защита от того, что петля фальсификации сама станет добровольной.

## E6 — chaos фаза 2 (1.5–2 ч, но поменять прицел)

Тут в плане недоопределение: «ENOSPC через tmpfs-квоту» на CI непереносимо (нет root, /dev/shm не перемонтировать). Честнее и сильнее — **моделировать I/O-сбой его следствием на диске** (порча состояния), плюс два реальных отказа:

| Класс | Механика | Портативность |
|---|---|---|
| state-corruption | сид выбирает файл (status / events.log / corpus.json / escapes.md / сирота `.tmp`) и порчу: обрыв строки, мусор, пусто → recovery + check_invariants | полная, детерминированная |
| remote-failure | REMOTE → недоступный URL / bare-репо `chmod -w` → run/merge обязаны упасть **чисто**: rc≠0, run.lock снят, worktree цел, doctor жив | полная |
| quota | `( ulimit -f 1; exec devh run … )` → SIGXFSZ на записи | если платформа не даёт — **SKIP с причиной в логе**, не FAIL (канарейка не должна краснеть от среды) |

State-corruption — главный класс: «частичная запись» и есть обрыв строки в status/events.log, а инварианты A7 (`fold(events.log)==status`, no-torn, no-tmp-сироты) уже написаны — ты их просто начинаешь бить **направленно**, а не в надежде, что случайный kill -9 попадёт в окно между write и rename.

**Приёмка:** 3 класса × 5 сидов зелёные; `devharness-chaos.yml` получает matrix `{kill, io}`; быстрая секция 45b (corruption) в test.sh.

**Честная оговорка для rust_build.md:** это покрывает *следствия* I/O-сбоев, инъекция *в момент записи* придёт только с портами эффектов (v2). Сейчас это лучший доступный уровень без rewrite — и он реальный апгрейд «дым → направленный стресс».
